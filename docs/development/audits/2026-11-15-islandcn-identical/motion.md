## Hardest items, and why

1. **Per-property curves (M1), via-idle (M3) and tails (M4) cannot stay on the outline alone.** The Core Animation outline (`IslandOutlineHost`) can take any per-component progress arrays, because it already samples paths at 120 Hz (`OutlineCurve.sampleRate`). The SwiftUI content cannot: the wings' cover and equalizer are laid out by SwiftUI on the transaction's single `Animation`, and masked by the CA outline. If the outline gets a width/height/corner curve the SwiftUI frame does not share, the content drifts against its own edge (the "no content past the edge" hard rule). Options: (a) pass the profile through a custom `TransactionKey` and drive the SwiftUI content from the same sampler with macOS 15's `CustomAnimation`; (b) move the pinned content to CA layers. Either is a rewrite of the content pinning, not a spring table.
2. **Content follows the container (C3) and regions (C2).** Scaling each slot by `(widthRatio x heightRatio)^(0.5)` per frame needs the live shape size, but the live shape runs on the render server off the main thread, by design. Reading it on the main thread undoes the "island lags while I work" fix; computing it from the same sampler per frame needs a `TimelineView`/display link on the main thread. The blur is the costliest part (Theme.swift documents animated blur as "among the costliest things SwiftUI draws"); blur 17 at peak on content is the one the owner already cut from the HUD.
3. **Two-Gaussian blur skirt (C4).** Needs a second, wider blurred copy of each slot added with plus-lighter. `CALayer.filters`/`compositingFilter` can do it, but only for layer-backed content with Core Image filtering on, and it doubles the layers on screen during every transition.
4. **The bubble as one liquid shape (A4).** Today the bubble and neck are a separate SwiftUI tree masked off the island. islandcn's pinch needs the pill's trailing edge, the bubble's leading edge and the neck in one animated path. On Core Animation, keyframed `path` values must keep the same command structure at every sample, so the neck must always exist as a degenerate subpath (width 0 once `gap >= maxGap`), and the continuous-corner path (fixed arc + cubics) is fine but the concave top shoulders of both shapes have to join the same structure.
5. **Top-attached shape means `top` legs, `collapseLift`, `bubble.collapseSplitLift` and the press swell need a notch-specific translation.** Swell must grow from the top edge; `top` tails become either height wobble or are dropped. Hit region and window padding must cover the swelled shape.
6. **Timing knock-ons.** Tails and via-idle lengthen a fold to about 0.75 s; `collapseRectShrinkDelay 0.45`, `expandSettle 0.5`, `OutlineCurve.longestChange 3` and the close-delay tests (`PanelCloseTests`, `MotionValuesTests`) assume the current spring and must be re-derived.
7. **Decisions islandcn's numbers contradict.** (a) Reduced motion: islandcn's 0.2 s ease-out cubic reintroduces the F-055 first-frame jump that Isla's 0.24 ease-in-out was chosen to avoid. (b) HUD pop-up: owner's "no delaying" (2026-10-25) versus `appearExpand` 0.54 and its content delays. (c) The keyline fades with wallpaper luma in islandcn; the owner chose a wallpaper-independent line. (d) The click-fold currently never uses `collapse` because `wasAlert` is never passed; fixing it changes behavior the owner has already seen.
8. **Digits (C6).** `numericText` is system-owned; islandcn's per-digit blur/scale/delay turnover needs per-digit views driven by a clock. The plan's claim that they are "the same motion" should be corrected.
9. **No ground truth on the notch.** All fits are to the iPhone simulator's frames at 94.85 x 36.84; the notch is 180-200 pt wide and 32-38 pt tall, so `compact` paddings and the `balance` rule have to be re-derived from the real sensor width, and every visual check is owed on hardware.
