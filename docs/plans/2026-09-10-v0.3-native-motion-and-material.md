# Isla v0.3 "It Feels Like Apple Built It" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the design gaps that keep Isla reading as a very good third-party utility rather than as something Apple shipped — starting with the one that is categorical rather than cosmetic: the artwork must be one object that travels, not two objects that crossfade.

**Architecture:** The diagnosis behind this release is that the app's design thinking is excellent per decision and absent as a system. Every constant carries a paragraph naming the bug that set it, but there is no shared vocabulary: 15 distinct font sizes, two `formatTime` implementations, two artwork views for one album, and Increase Contrast reaching exactly two `strokeBorder` calls. Each task here replaces a set of local decisions with one rule applied everywhere. The exception is Task 1, which is not consolidation but the missing thing: `matchedGeometryEffect`, of which the repository currently contains zero uses.

**Tech Stack:** Swift 6.0 tools / language mode v5, `platforms: [.macOS(.v15)]`, SwiftPM only, XCTest, SwiftUI + AppKit.

## Global Constraints

- All commands run from inside `.worktrees/dynamic-island-parity`.
- Work happens on `feat/…` or `fix/…` branches merged back with an explicit merge commit. Never commit to `main` or `staging`.
- Commit subjects are lowercase sentences describing the user-visible result. Bodies explain the mechanism and name the tests that hold the invariant.
- Every user-facing string is localized in **both** `Resources/en.lproj/Localizable.strings` and `Resources/ru.lproj/Localizable.strings`. Keys **are** the English text. `Scripts/test-localizations.sh` enforces key parity.
- `Scripts/test-branding.sh` fails on any case-insensitive `cyclop` match **and** on the former product name `Dynamic Island`, under `Sources`, `Resources`, and the named scripts — including in comments.
- Translucent surfaces go through `glassSurface(...)`. Never hand-mix another gradient.
- **Springs stay critically damped.** `Theme.swift`'s opening comment states Apple's rule from *Designing Fluid Interfaces*: overshoot is for gestures that carried momentum. `MotionValuesTests.testNothingWithoutMomentumOvershoots` enforces it. A click carries no momentum. The one place a bounce is defensible is Task 3's lyrics page, which is carried by the song.
- Reduce Motion, Reduce Transparency and Increase Contrast are read from `SystemAppearance.shared`, not from SwiftUI's environment — the environment carries only Reduce Motion on macOS.
- The design doc `docs/plans/2026-08-18-dynamic-island-parity-design.md` is amended **in place, dated, never rewritten**.
- Definition of done for every task: `swift test` has actually run and passed, and its output was read.

## UNRESOLVED — decide before Task 5, does not block Tasks 1-4

`Theme.tracking(forSize:)` hand-applies an SF-shaped tracking table because SwiftUI's automatic tracking reaches the semantic text styles and not `.system(size:)`. The 2026-09-03 audit's restraint critic argued this rests on a false premise and that the app should delete the table and match the platform exactly; the difference measured is ≤0.35 pt per glyph.

I am **not** confident the critic is right. Apple does publish per-size tracking values, so hand-applying them is arguably *more* faithful than omitting them, not less. Deleting the table changes every label in the app for a reason nobody has demonstrated.

**Task 5 therefore keeps the table** and only consolidates sizes into roles. If you want the table gone, that is a separate change with its own before/after screenshots.

**Background:** `grep -rn "matchedGeometryEffect\|@Namespace" Sources/` returns **zero hits**. Today the 22 pt `compactArtwork` shrinks and fades in place while a *different* 118 pt cover in `MediaPane.artwork(for:)` fades up and across — same album, two objects, crossfading past each other. This is the single thing Apple's island is known for, and the app does not do it.

**This task is deliberately not fully specified.** The correct placement depends on the real view tree, which you must read. The requirement is behavioural: for one frame during the open, source and destination must coexist in the tree so SwiftUI can interpolate between them.

```swift
import SwiftUI
import XCTest
@testable import IslaKit

/// The cover is one object that travels between the pill and the panel.
///
/// It used to be two: a 22 pt cover in the compact header and a 118 pt cover in
/// the media pane, each fading independently, so the same album crossfaded past
/// itself on every open. No unit test can watch an interpolation, so what is
/// pinned here is the contract that makes one possible — a single shared
/// geometry identity, and both ends agreeing on it.
@MainActor
final class ArtworkMorphTests: XCTestCase {

    /// Both ends of the travel are described by one function, not by two
    /// hardcoded pairs. Today the pill hardcodes 22pt/r6 in `NotchContentView`
    /// and the pane hardcodes 118pt/r14 in `MediaPane` — two descriptions of one
    /// object, which is the same mistake as two views of one cover, one level
    /// down. A matched geometry effect interpolates the frame for you; what it
    /// cannot do is notice that the two ends disagree about what they are.
    func testOneFunctionDescribesBothEndsOfTheTravel() {
        let compact = Theme.artworkMetrics(isOpen: false)
        let open = Theme.artworkMetrics(isOpen: true)

        XCTAssertLessThan(compact.side, open.side, "the pill's cover is the smaller end")
        XCTAssertLessThan(compact.cornerRadius, open.cornerRadius)

        // The corner stays proportional across the travel, so the silhouette is
        // the same shape at both ends rather than two different roundnesses
        // that happen to meet.
        let compactRatio = compact.cornerRadius / compact.side
        let openRatio = open.cornerRadius / open.side
        XCTAssertEqual(compactRatio, openRatio, accuracy: 0.02,
                       "the cover keeps its proportions while it travels")
    }

    /// Reduce Motion must not leave the cover mid-flight: with travel switched
    /// off the two ends still have to resolve to one of them, not to a frozen
    /// interpolation. `Theme.open(reduceMotion:)` is what decides that, and it
    /// must stay a real animation rather than `nil`.
    func testReduceMotionStillAnimatesTheOpen() {
        XCTAssertNotNil(Theme.open(reduceMotion: true))
        XCTAssertNotNil(Theme.open(reduceMotion: false))
    }

    /// The pane still renders without a namespace, so the existing render
    /// tests and the lock card keep working.
    func testTheMediaPaneRendersWithoutANamespace() {
        let stores = NotchStores()
        guard let geometry = NotchGeometry.current() else {
            return XCTFail("a test host always has a screen")
        }
        let vm = NotchViewModel(geometry: geometry, stores: stores)
        let pane = MediaPane(vm: vm, morph: nil)
        let image = ImageRenderer(content: pane.frame(width: 560, height: 157)).nsImage
        XCTAssertNotNil(image, "MediaPane must render with morph: nil")
    }
}
```

```swift
import SwiftUI
import XCTest
@testable import IslaKit

/// Contrast ratios for the tokens the chrome is built from.
///
/// The panel is white-on-black, so a token's ratio against black is computable
/// and worth asserting: `surface` at white 0.08 is 1.14:1, which is a shape
/// nobody can see. This is not only an accessibility question — the selected
/// tab chip and the empty scrubber track are drawn from these tokens.
@MainActor
final class ContrastRampTests: XCTestCase {

    /// WCAG relative luminance for a grey of the given white opacity over black.
    private func ratioOverBlack(whiteOpacity: Double) -> Double {
        let channel = whiteOpacity
        let linear = channel <= 0.03928
            ? channel / 12.92
            : pow((channel + 0.055) / 1.055, 2.4)
        return (linear + 0.05) / 0.05
    }

    func testTheNonTextChromeIsVisibleAsAShape() {
        XCTAssertGreaterThanOrEqual(
            ratioOverBlack(whiteOpacity: Theme.surfaceOpacity(increaseContrast: false)), 1.4,
            "a filled chip has to read as a filled chip"
        )
        XCTAssertGreaterThanOrEqual(
            ratioOverBlack(whiteOpacity: Theme.surfaceHoverOpacity(increaseContrast: false)), 2.0
        )
    }

    func testIncreaseContrastRaisesEveryTokenItShould() {
        for pair in [
            (Theme.tertiaryOpacity(increaseContrast: false), Theme.tertiaryOpacity(increaseContrast: true)),
            (Theme.secondaryOpacity(increaseContrast: false), Theme.secondaryOpacity(increaseContrast: true)),
            (Theme.surfaceOpacity(increaseContrast: false), Theme.surfaceOpacity(increaseContrast: true)),
            (Theme.hairlineOpacity(increaseContrast: false), Theme.hairlineOpacity(increaseContrast: true)),
        ] {
            XCTAssertGreaterThan(pair.1, pair.0, "Increase Contrast must raise this token")
        }
    }

    /// 9pt labels are the type least able to afford a low ratio, and they carry
    /// most of the panel: tab titles, counters, scrubber times, placeholders.
    func testTheSmallestLabelClearsWCAGAAAtEverySetting() {
        for contrast in [false, true] {
            XCTAssertGreaterThanOrEqual(
                ratioOverBlack(whiteOpacity: Theme.tertiaryOpacity(increaseContrast: contrast)), 4.5,
                "tertiary carries 9-10pt labels and must clear AA"
            )
        }
    }

    /// The dimmest lyric context line. At white 0.18 it was 1.54:1.
    func testTheLyricFalloffHasAFloor() {
        XCTAssertGreaterThanOrEqual(
            ratioOverBlack(whiteOpacity: LyricRow.falloffFloor(increaseContrast: true)), 3.0
        )
    }
}
```

func formatTime(_ seconds: TimeInterval) -> String {
    guard seconds.isFinite, seconds >= 0 else { return "--:--" }
    let total = Int(seconds.rounded())
    let hours = total / 3600
    // A podcast is the case this exists for: without the roll, a two-hour
    // episode drew "120:45" into a gutter sized for "59:59" and came out as
    // "120:…". Under an hour the leading "0:" would be noise, so it is left off.
    guard hours > 0 else { return String(format: "%d:%02d", total / 60, total % 60) }
    return String(format: "%d:%02d:%02d", hours, (total % 3600) / 60, total % 60)
}
